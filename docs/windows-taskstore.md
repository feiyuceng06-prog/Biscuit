# Windows TaskStore design (pre-implementation)

Keep schema 1, checksums, revision and restore logic. Linux stays on existing dir_fd/flock/fsync path. Add lazy-imported stdlib ctypes adapter, local NTFS only; reject UNC, device paths, alternate streams, reparse points, nonregular files and multi-link state files. Inspect BY_HANDLE_FILE_INFORMATION, not path stat, for volume/file index and attributes. Open every ancestor with OPEN_REPARSE_POINT and retain handles without write/delete sharing throughout a guarded operation; retain session chain for writer lifetime. This prevents directory replacement and reparse mutation during path-based child calls. Unsupported layouts fail closed.

Create private directories using SECURITY_ATTRIBUTES carrying protected DACL with inheritable current-token-user full control only; existing directories have owner verified before applying this DACL by handle. Accept the token user or TokenOwner default owner (Windows elevated tokens commonly default to Administrators); require WRITE_OWNER and set the owner to the current user together with the protected DACL. This is an on-demand metadata migration, with no privilege enablement and no arbitrary-owner takeover. Payloads and legacy histories are not rewritten. No chmod approximation. New temp files inherit private parent; existing state files must be single-link. Writer.lock uses CreateFile OPEN_ALWAYS with share=0 and a handle held for store lifetime: excludes other processes and auto releases on crash. Directory handles also prevent writer-lock path substitution by moving its parent. Same-user malicious processes and administrators can change ACLs; not a boundary against them.

Write UTF-8 temporary file in guarded private directory, flush Python bytes then FlushFileBuffers via os.fsync, close temp, MoveFileEx(REPLACE_EXISTING|WRITE_THROUGH) within same NTFS directory, reopen result and FlushFileBuffers. A failed stage blocks the store, including failures after replace. No fallback to ignoring errors. No assertion that Windows directory fsync exists: guarantees process-crash atomic old/new snapshots and explicit file-data flush requests, NOT sudden-power-loss ordering of directory entries or faulty-device cache survival. After machine/power failure revalidate every checksum/identity and restore prepared/running as unknown; no replay or budget refund. Publication requires independent review of this weaker metadata-durability boundary.

Legacy session snapshots remain read-only on restore; no eager history migration, task schema unchanged. Workspace identity uses volume/file index through checked descriptor. Tests must exercise native runner (cross-process exclusivity/crash release, reparse/hardlink rejection, stale revision, failure windows and synthetic send), then existing frozen/GUI/installer gates. No real user data, provider requests or local installs.
